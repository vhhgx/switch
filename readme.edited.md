# Claude-Proxy-Switcher

🚀 Claude Code CLI 多账号/多中转站自动故障转移网关 —— **完美适配 New API 生态**

一个基于 Koa3 的本地中间件工具，作为 Claude Code CLI 和 Anthropic API 之间的智能代理。特别针对基于 **New API**（及 One API 等衍生框架）搭建的各类中转站进行了深度适配，轻松实现多账号自动切换、故障转移和统一调度管理。

---

## ✨ 核心特性

### 1. 🥇 完美兼容 New API 框架
- **无缝对接**：全面支持所有基于 New API / One API 搭建的中转站点。
- **生态适配**：支持解析 New API 的标准报错格式，精准触发重试机制。
- **账号管理**：原生支持 New API 中转站的余额查询、额度统计以及每日自动签到功能。

### 2. 🔄 智能故障转移（Failover）
- **自动检测**：精准识别 API 错误（401/402/404/429/5xx）及网络超时。
- **无感切换**：当前中转站失败（如额度耗尽、触发限流）时，自动秒级切换到下一个可用中转站。
- **极高可用**：只有当配置池中所有中转站都不可用时，才会向客户端返回错误。

### 3. 🌊 原生流式传输与 Header 透传
- **SSE 支持**：完整支持 Server-Sent Events (SSE)，实时流式响应透传。
- **计费无忧**：精准透传 `anthropic-*` 等响应头，确保前端客户端或 CLI 能够正确统计 Token 消耗和额度。

### 4. 🛠️ 全自动化配置管理
- **系统环境变量**：跨平台（Win/Mac/Linux）一键写入/删除 `ANTHROPIC_BASE_URL` 等环境变量，告别手动配环境。
- **Claude 配置覆写**：自动定位并更新 `~/.claude/settings.json`，一键注入所需参数。
- **网络隔离**：强制禁用 Axios 代理（`proxy: false`），防止系统全局代理造成请求回环。

### 5. ⚡ 智能请求拦截与路由优化
- **拦截 `count_tokens`**：自动拦截 CLI 发出的 `/v1/messages/count_tokens` 请求并返回默认值。避免由于多数中转站不支持该接口而导致的 404 报错，显著提升响应速度。
- **模型映射转换**：支持为每个中转站独立配置模型别名映射（如 `claude-3-opus-20240229` 自动转为 `claude-opus-3`），轻松应对不同站点模型命名不一致的问题。
- **URL 智能清洗**：自动处理 BaseURL 末尾斜杠，清洗重复的 `/v1/v1/` 路径拼接。

## 📦 安装与启动

```bash
# 1. 克隆或下载项目
git clone <your-repo-url> claude-proxy-switcher
cd claude-proxy-switcher

# 2. 安装依赖
npm install

# 3. 启动服务
npm start
```

**💡 首次启动说明：**
系统采用**零配置启动**设计。首次运行时会自动在根目录创建 `providers.json`（中转站配置）和 `settings.json`（应用设置）。控制台会输出初始化状态及服务监听端口（默认 `5678`）。

## 🔧 使用指南

### 1. 访问管理后台

服务启动后，在浏览器中访问：`http://localhost:5678`

### 2. 添加 New API 中转站

在可视化管理界面中直接配置：

* **名称**: 自定义（如 "NewAPI-主站"、"备用渠道A"）
* **Base URL**: 填入中转站地址（如 `https://api.your-new-api.com`，带不带 `/v1` 均可，系统会自动处理）
* **API Key**: 对应渠道获取的令牌凭证

### 3. 一键配置 Claude Code CLI（推荐）

进入管理界面的 **“设置”** 页面，点击一键配置。系统会自动为您：

1. 配置操作系统环境变量。
2. 更新 Claude Code 的配置文件，将 API 地址指向本地网关。

*(若需手动配置，请将 `apiUrl` 或 `ANTHROPIC_BASE_URL` 设为 `http://localhost:5678`)*

## 🎯 架构与工作原理

**请求流转逻辑：**

1. Claude CLI 发起请求 -> 本地代理网关拦截。
2. 网关读取配置池中所有 `enabled: true` 的中转站。
3. 按照优先级或顺序发起请求。
4. 若遭遇 `401/402/429/5xx` 或超时，**网关拦截报错，自动切换至下一个中转站**。
5. 获取成功响应后，通过流式传输透传回客户端；并异步触发账户余额检查。

## 🔍 常见问题排查 (FAQ)

**Q: 所有中转站都请求失败？**
**A:** 请检查您的 Base URL 是否可达，API Key 是否正确填写。若使用国内网络请求境外直连站点，请检查本地代理设置。

**Q: 遇到 "model not found" 错误？**
**A:** 不同的 New API 站长可能对型命名有差异。请在 `providers.json` 中使用 `modelMapping` 字段，将官方名称映射为该站长支持的名称。

**Q: CLI 频繁报错 404？**
**A:** 通常是因为 CLI 发送了 `count_tokens` 请求。请确保您拉取的是最新版本，当前版本已内置请求拦截，直接返回模拟数据。
